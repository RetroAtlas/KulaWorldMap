# The level editor

What the editor's files hold and what its writers put on the disc, reading by reading, with what each rests on. The project file is the editor's permanent record of a level and this document is its specification, so that a reader outside this repo can read one; the level file is the game's own bytes, and the rules for writing it from a project and reading a project out of any file the game would load are here, with the words the game never reads named and the checks that hold both writers to the disc. [level-format.md](level-format.md) is where the readings of the game's file come from, and `tools/kula_kwl.py` is the Python writer every figure here was measured with.

## The project file

A project is a JSON document with the extension `.kula.json`. It spells the game's own structure in the game's own numbers: cells are lattice coordinates with `z` counting down, kinds and types are the numbers the game uses, faces are the game's six.

```json
{
  "format": "kula-world-level",
  "version": 1,
  "title": "Spiral",
  "author": "",
  "notes": "",
  "world": "HIRO",
  "into": "/HIRO/HIRO.PAK#0",
  "from": "/HIRO/HIRO.PAK#3",
  "time": 99,
  "hidden": false,
  "invisibleFromAfar": false,
  "circuits": { "1": "off" },
  "blocks": [
    { "cell": [17, 12, 17], "kind": 0, "faces": { "0": { "type": 30, "facing": 3 } } },
    { "cell": [17, 13, 17], "kind": 0, "faces": { "0": { "type": 37, "variant": 2 }, "5": { "type": 5, "facing": 4, "variant": 1 } } },
    { "cell": [17, 14, 17], "kind": 2 },
    { "cell": [20, 12, 17], "kind": 6 },
    { "cell": [21, 12, 17], "kind": 7, "phase": 1 },
    { "cell": [10, 12, 17], "kind": 5, "far": [10, 16, 17], "length": 2, "speed": 30 },
    { "cell": [10, 20, 14], "kind": 8, "far": [14, 20, 14], "colour": 3 }
  ]
}
```

| key | meaning | default on read |
| --- | --- | --- |
| `format`, `version` | the marker `kula-world-level` and the integer 1; a reader refuses any other marker | required |
| `title`, `author`, `notes` | the author's; the game never shows them | `""` |
| `world` | one of the ten disc ids, `HIRO`, `HILLS`, `INCA`, `ARCTIC`, `COWBOY`, `FIELD`, `ATLANT`, `HAZE`, `MARS`, `HELL`: the artwork, the ball and the music | required |
| `into` | the target slot on the disc, in the repo's `pack#index` form, a world pack's slot 0 to 19 or a finals pack's 0 or 1; the Simon rooms' pack is refused | none |
| `from` | where a template came from, the shipped level's `pack#index` | none |
| `time` | seconds, which the game multiplies by 50 into its clock | 99 |
| `hidden` | the settings record's type 1: the glass ball and translucent faces | `false` |
| `invisibleFromAfar` | the settings record's `f2` 1: invisible blocks show from afar and fade near the ball | `false` |
| `circuits` | per colour `"0"` to `"3"`, yellow, blue, green, red, `"on"` or `"off"`; a colour not named starts on | `{}` |
| `blocks` | the sparse lattice, one entry per placed cell | required |

A block is `cell`, three coordinates each 1 to 32, and `kind`, 0 to 8: 0 plain, 1 fire, 2 ice, 3 invisible, 4 acid, 5 moving platform, 6 crumbling, 7 vanishing, 8 laser; the settings kind 9 is never a block. A block of kinds 0 to 4 may carry `faces`, keyed by the game's face numbers `"0"` to `"5"`, top, `+x`, `+y`, `-y`, `-x`, underside, each `{ "type", "facing", "variant" }`: `facing` is 1 to 4, a quarter turn at a time about the face's inward normal from its first tangent ([level-format.md](level-format.md)), on the types that turn, the teleporter 5, the arrow 28, the two starts 29 and 30 and the captivators 50 to 53 and 56, since the lift at `0x8003b5dc` gives each captivator its heading from the word and the wandering ball's walk follows it; a wandering ball or a corkscrew with no facing heads as 1 does, which is how the disc leaves most of them, since the captivators' routine at `0x8003f98c` turns for a word of 2, 3 or 4 alone ([motion.md](motion.md)), as do the two stars and the wheel, whose heading comes through the same routine, and so does what the start's routine at `0x80038178` turns, the starts and the teleporter, which turns for the same three words; the arrow is taken to follow the same pattern unverified, since no routine this repo has read turns it and no arrow on the disc carries a 0, so every reader of this repo reads a facing of 0 on a type that needs one as 1, with a line saying so; `variant` is what the type's one varying field holds, the colour 0 to 3 of a teleporter 5 or a switch 9, the tier 2, 1, 0 of a coin 37 for bronze, blue, gold, the cut 0, 1, 2 of a gem 36 for blue, green, red, and the phase 0 to 3 of the moving spikes 11 and the corkscrew 56. A vanishing block carries `phase`, 0 to 3 on the disc, 4 and 5 accepted as "dims at once". A platform carries `far`, the other end of its run, `length` in blocks, 2 or 3 on the disc, and `speed`, 30 on the disc, a step the game scales by 50/60 and adds to the position each frame. A laser carries `far` and `colour`. The record's own cell is one end of a span and `far` the other, on one axis, and the span is read from the two whichever is lower.

The writers of this repo write a project the same way, so a diff between two is a diff between levels: blocks in lattice order, ascending `x`, then `y`, then `z`, which is also the game's record order; `facing` only on a type that turns and only where the word is not 0; `variant` on every type that has one, 0 included; `length` and `speed` always on a platform; `circuits` holding only the colours that start off; `from` where there is a source. A template of a shipped level takes its `title` from the number the pause screen shows, or the disc's name where the game shows none.

**The growth rule.** Keys are only ever added; a published key never changes its meaning or its type; every optional key has a default on read; a reader ignores keys it does not know. `version` stays 1 for as long as that holds, which is meant to be forever; it exists so that a reader meeting a higher number can say the file is newer than it, read what it knows and warn rather than misread it.

**Reading a project file.** `readProject`, and `read_project` in the tool, refuse a document that does not carry the marker and take everything else, with a report line for every value it could not take as written: a key of the wrong type takes its default, so `"length": "3"` is a two-block platform and a `time` that is not a whole number is 99; a colour or a variant outside its range is 0; a face key that is not one of the six, a second spelling of a face already named, and a face entry with nothing standing there, a type of 0 or none, are left out; a block without a cell of three whole numbers and a kind is left out, and so is a span with no far end, or one on its own cell or outside the lattice, since the writer has no bytes for either; a key the reader does not know is passed over in silence, and a higher `version` is read with a line saying so. Lines of one shape are kept to the first three and the rest counted, as the level reader's are. What comes out is a project the writer writes, and the checks name what the game would make of it.

## What is never stored, and why

Everything the game derives at load or never reads is left out and rebuilt at every write, so that a file cannot carry a stale copy of it: the links between switches, teleporters and lasers (a stale one hangs the game or sends the ball into garbage, [level-format.md](level-format.md)); the pickup numbers (the loader renumbers everything it walks at `0x80035998`); each device's own state word (a colour turns over as one, so the colour's state is what is stored); the header word (unread, [the backlog](../backlog/item-005-the-header-word.md)); the trailer's cell and two numbers (unread); the sixteen never-set words, the extras and the filler words of every slot; record order (lattice order at every write); the beam's cells (the loader writes them at `0x80035a70`); a span's direction, axis and end order (derived from `cell` and `far`); the crumbling block's copy of its own cell; the level type (derived from the key count); names, since names change and numbers do not; and any id local to one browser, since a file is a level and not a slot in someone's browser.

## The level file a project means

A `.kwl` is the inflated level exactly as the game loads it, the one form every community tool shares. `canonical(project)` writes one file for a project and writes it the same way every time, so two writers that agree on the rules below agree to the byte.

**The container.** The lattice of 39,304 little-endian `u16` cells indexed `x*1156 + y*34 + z`, `0xFFFF` where nothing stands, 0 to 4 for a block of that kind with nothing on it, and `5 + i` for the block carrying record `i`; a beam's cells and the rest of a platform's run are left empty, since the loader fills them. Then the header, an `i32` holding the placed-cell count, which the game never reads, and the `u16` record count, which excludes the trailer. Then the records, 256 bytes each: every block of kinds 5 to 8 and every block of kinds 0 to 4 with something on a face, in lattice order, then the settings record where `hidden` or `invisibleFromAfar` is set and otherwise no settings record at all, then the trailer. The file is `78614 + 256 x (count + 1)` bytes long.

**A record** is 128 `i16` words: six slots of sixteen at words 0 to 95, the never-set words 96 to 111 at -1, the extras 112 to 124 at -1, and the cell at 125 to 127. A slot's words are the kind word, the type, the fields `f2` to `f12`, a pad, `f14` and a pad. The six slots are the six faces in the order above.

| kind | slot 0 | slot 1 | slots 2 to 5 | extras |
| --- | --- | --- | --- | --- |
| 0 to 4, a bare face | `[K, 0, -1, -1, 0, -1, -1, -1, 0, -1 x7]` | the same with -1 for K | the same | -1 |
| 0 to 4, an object | `[K, type, facing, variant, state, number, next, link, 0, F9, F10, -1, -1, -1, F14, -1]` | the same with -1 for K | the same | -1 |
| 5 platform | `[5, dir, axis, 1, lx, ly, lz, ux, uy, uz, -1 x6]` | `[end, length, speed, -1, 5 + k, -1 x11]` | -1 x16 | words 119 to 121 `512 x cell`, 122 to 124 `256` |
| 6 crumbling | `[6, 1, 512x, 512y, 512z, -1 x11]` | -1 x16 | -1 x16 | -1 |
| 7 vanishing | `[7, 0, phase, -1 x13]` | -1 x16 | -1 x16 | -1 |
| 8 laser | `[8, dir, axis, lit, lx, ly, lz, ux, uy, uz, -1 x6]` | `[-1, 1, -1, -1, 5 + k, -1, colour, next, -1 x8]` | -1 x16 | -1 |
| 9 settings | `[9, hidden, flip, 0 x13]` | 0 x16 | 0 x16 | 0, and the cell `0, 0, 0` |
| 666 trailer | `[666, sx, sy, sz, 0, 0, time, -1 x9]` | -1 x16 | -1 x16 | -1, and the cell `-1, -1, -1` |

`K` is the block's kind in slot 0 and -1 in slots 1 to 5. A face with nothing on it on a block of kinds 0 to 4 is the bare slot, the form the disc holds on 19,851 of its empty faces, and the game tests only its type 0 and its state 0; the slots a record of kinds 5 to 8 has no use for are -1 throughout, which is what the disc holds on most of them, 32 to 33 of its 37 platforms, 337 to 402 of its 435 crumbling blocks, 40 to 93 of its 98 vanishing blocks and 116 to 117 of its 123 lasers by slot, the rest carrying an editor's leftovers in words the game never reads. `dir` is the game's direction from the record's cell to `far`, 0 `-z`, 1 `+x`, 2 `+y`, 3 `-y`, 4 `-x`, 5 `+z`; `axis` is 1, 2 or 5 for a run along `x`, `y` or `z`; `l` is the lower end and `u` the upper, lower first on all 160 spans of the disc; `end` is 0 when the record stands at the lower end and 1 at the upper, as on 37 of 37; `lit` is 1 where the laser's colour starts on and 0 where it starts off; `5 + k` is the record's own lattice value, which the platform loader at `0x80032908` writes over its whole run; `phase` is the vanishing block's; `hidden` and `flip` are the two settings; `sx, sy, sz` is the cell of the start the game takes, or `0, 0, 0` with no start; `time` is the project's. The trailer's cell words are -1, so every file ends `ff ff ff ff ff ff`.

**The words of an object slot by type.** `facing` is the project's where the type turns and 0 elsewhere; `variant` is the project's where the type has one and 0 elsewhere; `state` is `f4`, the word the draw and contact walks gate on at `0x80039280` and `0x80038580`, so a pickup with 0 there is neither drawn nor collected; `number` is the pickup's, below, and -1 on anything else; `next` and `link` are the links, below, and -1 on anything else; `f8` is 0, the frame the draw command carries; `F9`, `F10` and `F14` are the constants the disc holds for the type, which the loader overwrites or never reads.

| 28 arrow | paint | yes | | 1 | 256, 0, 0 |
| 29 start on a clock | start | yes | | 0 | 386, 1, -100 |

A type not in the table is written with state 0 and the constants -1, which is a slot the game skips.

**The links.** For each colour, the members are its switches and teleporters as `(record, face)` and its lasers as `(record, 6)`, sorted ascending, `M[0]` to `M[n-1]`, and `link(m) = record x 16 + face`. `next(M[0])` is -1 and `next(M[i])` is `link(M[i-1])`, written to `f6` of a device and to word 7 of a laser's second slot, so the list a switch walks runs down the members from the highest; every switch's `f7` is `link(M[n-1])`. The colour's teleporters sorted ascending, `T[0]` to `T[m-1]`, send the ball round one ring, `f7(T[i]) = link(T[(i-1) mod m])`, a lone teleporter naming itself. This is the rule the disc's 104 switches and 147 teleporters follow without exception ([level-format.md](level-format.md)), and `Level.verify` holds every written file to it.

**The pickup numbers.** Walking the records in order and the faces 0 to 5 of each, the fourteen pickup types, 31 to 38 and 42 to 47, take `f5` of 0 to n-1 and every other slot -1. The disc numbers its pickups the same way on 224 of its 228 levels that have any, the four exceptions carrying a repeat on an object the game never walks, and the loader renumbers at load in any case.

**Undefined bytes.** A project whose cells lie outside 0 to 33, that puts two blocks on one cell, that names one face of a block twice, as `"5"` and `"05"` do, whose span runs along no one axis or has no far end or one outside 0 to 33, or that asks of any word more than -32768 to 32767, the file's range, as a time or a platform's length or speed can, has no level file, and `canonical` raises rather than invent one; `validate` names each of these as an error first.

## Reading a file the game would load

`read_kwl(blob)` reads what the game reads and repairs what the lattice contradicts, and tells the caller what it did in a report, a line per repair, where lines of one shape, the same words with other numbers, are kept to the first three and the rest counted in one line after them, so a hostile lattice does not give a report the length of itself. The game walks the lattice by value and the records by the count, so the lattice is the authority for where a block is and which records exist; the community's files break the parser's rules in ways the game shrugs off, so only one thing is fatal.

- Any length that is the lattice, six bytes and whole 256-byte stretches reads; the stretch count comes from the length, and a header count that disagrees is a report line. Any other length raises.
- The last stretch is the trailer where its kind is 666; otherwise none is there, the time is 99 and the report says so.
- A settings record anywhere among the records gives the two flags, and several give the flags of all of them.
- A record whose cell words differ from the cell naming it is moved to that cell; a cell naming a record that is not there, or that another cell names first, or that is not a block, is left empty; a record no cell names, the settings record apart, is dropped. Each is a report line.
- A span's two ends are read from `f4` to `f9` and sorted lower first; `far` is the end that is not the record's cell, and a record standing at neither end has its lower end moved onto its cell, reported. A span whose two ends are both its own cell, or whose far end lies outside the lattice, is dropped and its cell left empty, reported, since the loader would write past the lattice for it. The direction and axis words are never read.
- A platform's length and speed are kept, and reported outside 2 to 3 and 30; a vanishing block's phase is kept, and reported at 4 or 5.
- Kinds 0 to 4 take an object from every face whose type is above 0, with its type whatever it is, its facing where the type turns and the word is not 0, read as 1 with a line where the type needs one and the word is 0, its variant where the type has one; what stands on records of kinds 5 to 9 is counted and left out, since the game never walks it; a record of kinds 0 to 4 with nothing on its faces folds into a plain block of its kind.
- A colour's state is read from its first device or laser, and a disagreement among them is reported.
- A file whose records are not in lattice order is written back in lattice order, and the report says so where the order decides play: where the file holds captivators, whose dice follow the walk order, or several starts, of which the game takes the last.
- The pickup numbers, the links, the filler words and the header word are never read.

## What the game would make of a project

`validate(project, hides)` returns findings, each a level, a text and where it is, a cell and perhaps a face; errors are what the game would mishandle, warnings what an author should know. `counts` gives the figures the caps are read against and `plays_as` the line the editor shows.

**Errors.** A cell outside 1 to 32, since the face builder at `0x800271d8` walks 1 to 32 and builds nothing beyond; two blocks on one cell; a kind that is not 0 to 8; anything on the faces of a block of kinds 5 to 8; a face key with something standing under it that is not one of the six, by number or by spelling; a face named twice; a type the game does not play, which is anything but the 32 types the disc places and the acid patch 4; a device, 5, 7 or 9, or the moving spikes 11 on a block that is not plain, since the glow loader at `0x8002977c` and the spikes' init at `0x8002a0b0` take kind 0 alone; a `facing` outside 1 to 4, or none on the teleporter, the arrow, the starts, the two stars and the wheel, which the disc always turns, the wandering ball and the corkscrew heading as 1 does with none; a `variant` outside its range; a laser's `colour` that is not one of the four; a `phase` outside 0 to 5; a span whose far end is its own cell, lies along no one axis or lies past the edge; a platform's run, lower end to upper end plus its length, reaching past the edge or holding any block but its own; a platform longer than 7 blocks, since the ride at `0x80033810` marks its run in an 8 by 8 by 8 grid at `0x800d4e30` by its length word and an eighth block lands past the row; a platform's length or speed outside the file's range; a beam crossing a block, or ending on a block that is neither plain nor another laser's, since the loader writes style 0 over both ends and `-2` between unconditionally; no start; a time below 1 or outside the file's range; a world that is not one of the ten; a target that is not a world or finals slot; and a counter over its cap, below.

**Warnings.** Several starts, naming the one the game takes, the last in record then face order; an object looking into a block, a crumbling or vanishing block or a beam's cell; a beam ending on a plain block that carries something, which keeps working but paints plain; a hidden exit 26 on a block that is not plain, which the glow loader passes over and the game has not been seen to take; a platform's speed other than 30 or length outside 2 to 3; a time above 99, which the clock has never been seen to show; a phase of 4 or 5; a colour that starts off with teleporters or lasers and no switch to turn it on; a lone teleporter leading to itself; a switch whose colour has nothing to switch; a key with no exit; the star 42, untested in play; a fruit, since the game shows the player's next whichever is placed; and a counter above the disc's own maximum, below.

The caps are the room the game's memory holds, unchecked by the game: the level's record table runs into the frame buffers at `0x80179000` after 123 records; the 160-byte face structs at `0x80191000` run into the per-cell table at `0x801af000` after 768; the 48-byte object entries at `0x800c8c78` run to the frame flag at `0x800cbc78`, 256 of them, and the loader zeroes the next entry's word before it reads each face, so the 256th object has the loader write past the table; the light maker at `0x8002e418` searches the 32 entries of the list at `0x800df184` for a free one and, finding none, falls through and writes the 33rd light past the list; the moving spikes' init at `0x8002a078` appends every type 11 on a plain block to the list at `0x800d655c`, which has room for 64 before the next table; the captivators' 180-byte entries at `0x800ba3dc` run to the next table after 32; and the crumbling and vanishing blocks' index lists at `0x800a5668` and `0x800a576c` hold 64 each before the tables that follow them. The caps on platforms, 8, and on the blocks a keyless level counts, 256, are conservative choices with no traced table behind them. The faces are counted as the loader builds them, replaying `skins.hides` of `public/objects.json` ([tgi.md](tgi.md)) over every block inside 1 to 32, a beam's two ends standing plain blocks first: a face toward a neighbour of a kind the block's kind hides behind is not built, except that a kind outside the table's own list is built unseen toward a crumbling block, a laser's own cell hides like the plain block the loader has made of it, which, with the ends standing plain blocks, is read off the loader at `0x80035a70` and untested in play, since no keyless level of the disc outside the Simon rooms, which score nothing, has a laser, and a platform's blocks take their faces from the loader's tables, six on a lone block and five, four and five along a run. HIDDEN 10 comes to 766 by that count, and one more plain block in the open takes it over 768.

**Plays as.** "Plays as an arcade level." where a key stands on a block of kinds 0 to 4; "Plays as a bonus level: it has no key, so every block scores 50 the first time the ball rolls onto it, the level ends once every block has been rolled, and an exit stands open from the start." where none does, by the loader's count at `0x80027b2c`; "Plays as a hidden level, with the glass ball on half-seen blocks." where `hidden` is set; and both clauses for a hidden level with no key.

## The drafts a browser keeps

The browser store is a convenience and the exported file is the record; the viewer's "Your levels" says so under its rows. `public/js/drafts.js` keeps the drafts under `localStorage["kula.drafts"]` as `{ "version": 1, "next": n, "drafts": { id: { "doc", "updated", "saved", "edits" } } }`: `doc` is a project as the file holds it, `updated` the time of the last change, `saved` the time of the last save to a file or null, `edits` the changes since that save, and ids are small integers taken from `next`, which only ever grows. A draft is drawn as `toLevel(doc, id)`, a level whose pack is `/DRAFT/DRAFT.PAK` and whose index is its id, so its permalink reads `#DRAFT/<id>/...` with no change to the link's grammar, and a module registered as a level source answers that slot on the device holding the draft; anywhere else the link falls back as any unhonoured hash does.

The store is read once at boot, through the same `readProject` the file importer uses: a store that does not parse is an empty one, and a draft whose document throws, or names a world that is not one of the ten, is never drawn but stays in storage as it is, each such draft counted into one toast. A browser whose storage throws on read keeps the drafts in memory alone and says they live until the page is closed. Writes wait 300 ms after the last change and are flushed on `pagehide`, on `visibilitychange` to hidden and through `flush()`, which an export calls first; a write that throws leaves the drafts in memory and says the browser is full once per streak of failures, not at every keystroke. A `storage` event for the key from another tab merges that tab's copy: per draft the later `updated` wins, a draft changed here since the last write is kept until that write, one deleted here is not taken back, and a draft of theirs under an id this tab handed out and never wrote is a level of its own, so this tab's draft moves to a fresh id with its steps and, where it is on screen, the view, and a toast says so. The store never reads the `kula.survey` key an earlier notebook left in some browsers. The steps a draft took, which undo and redo walk, live in the editor's memory alone (`public/js/trail.js`): one step a user action with a cap of 200, typed titles coalescing into one, never stored, never in a file, and dropped when the draft is deleted or another tab's copy of it is taken.

## Files

A draft saves as `<slug>.kula.json`, the project file `writeProject` writes, or as `<slug>.kwl`, the canonical level `writeKwl` writes; the slug is the title composed to NFC and in lower case, with every run of anything but letters, their marks and digits as one hyphen, cut to 60 characters, trimmed of hyphens, and `level` where nothing is left, and a shipped level exports its own `.kwl` the same way, through `fromLevel`, so `LEVEL 1` saves as `level-1.kwl`. Either save flushes the store first and then marks the draft saved, `saved` the time and `edits` 0, so its row counts the changes since. `public/js/files.js` opens a file by what it holds, never by its name, in the order "Levels from elsewhere" below gives: the map's own file is read by `readProject` and refused where its world is not one of the ten; the game's level is read by `readKwl` in the world on screen and titled by the file's stem; a pack, a disc image or a level of the community's viewer is read as that section says; JSON that is neither the map's file nor the viewer's is refused, as is anything the order places nowhere; and a document the writer cannot write is refused with the writer's reason. Every open makes a new draft marked saved, since the file is the record, and the reader's report shows as one toast, the line itself where there is one, and in full in a fold at the top of the Level card until another draft is shown.

## Onto the disc

A draft is exported to the disc by `public/js/patchdialog.js`, which refuses nothing but errors: a project with any error from the checks below is shown its errors and gets no patch, warnings go in a fold and stop nothing, and a project the writer cannot write is refused with the writer's reason. The target is the project's `into`, a slot of a world pack or a finals pack in the `pack#index` form, chosen in the dialog from `public/packs.json` with the Simon rooms' pack left out, defaulting to the project's `into`, else its `from`, else `/HIRO/HIRO.PAK#0`, and written to the draft through `setMeta` as any other field is, so the file carries it. The fit is worked out twice. Before the image is given, from `public/packs.json` alone through `fit(pack, slot, size, title)` with the length of the level's zlib stream at level 6, the level the disc was packed at, which decides the path and the bytes to spare from the slot's record, the name the slot would take from the title, the pack's capacity and the other records' lengths as stored and recompressed, and is never optimistic since a rebuilt pack's name table never grows. Once the image is read, through `openDisc` and `plan` over the image itself, inflating with the browser's `DecompressionStream`, which gives the same path and room where the image is the disc's and the truth where it is not, and whose warnings about an image that is not the disc's are shown and stop nothing. The patches are then the bytes of [disc.md](disc.md): the PPF with the description `Kula World Map: <title>`, the VCDIFF, and the patched image as the original's slices with the written sectors between them, each named `<slug>` with its extension and each download flushing the store first.

## Levels from elsewhere

`readLevelFile` reads a file by what it holds, in one order, and never by its name: a file of whole 2352-byte sectors with the volume mark at sector 16 is a disc image, sniffed first so that one handed over as a file is read a slice at a time rather than whole; text that parses as JSON is the map's file where it carries the marker and the community viewer's level where it has `blocks` at `pos` and a `time`; bytes whose first word counts 1 to 32 slots whose table, records and NUL-ended names all lie within the file are a pack; a length that is the lattice, the six header bytes and whole records is the game's level; and anything else is refused. A pack asks which slot to open, each named as the pack names it, and the chosen record is inflated with the browser's `DecompressionStream` and read by `readKwl` in the world on screen, since a pack's bytes do not say which world they are from, titled by the slot's name or the file's stem; a browser that cannot inflate is told it needs a newer one. A disc image is walked as the patcher walks it, a slice at a time where it is handed over as a file, and lists the packs it holds, the 21 the disc has and any other `.PAK` the walk finds, then the slots of the chosen pack, each titled as the pause screen titles the shipped level that lies there and by the pack's name otherwise; the chosen record is read in the world of the pack's directory, and in the world on screen for a pack from elsewhere. Declining either question opens nothing and says nothing. Every file opened this way makes a new draft marked saved, as the map's own file does, with the reader's report in the card's fold.

The community's Saturn viewer, orbit, keeps a level as JSON of blocks, and the same level in a share link. In the JSON, `type` is the game's kind, `pos` is the game's cell `(x, y, z)` written as `(x, 33 - z, y)`, and a block of kinds 0 to 4 carries six `items`, one a face, each the slot's words under the viewer's names, `id`, `option`, `variant` and `state` for the type, the facing, the variant and the state, with `route` and `to` for the two link words on a teleporter or a switch, 65535 where the file holds -1, and `null` where the link leaves a slot empty; a block with no item is the lattice's own and a block whose items are all bare is one too. A platform carries `from`, `to` and `start` as the game's points with `y` and `z` swapped and no flip, the last times 512 as the file has it, with `movement`, `orientation`, `length`, `speed` and `id` for the words the file holds under those meanings; a vanishing block carries its record's first eight words as `intervals`, the phase second; and a laser carries `from`, `to`, `orientation` and four words named `length`, `speed`, `variant` and `state` that are really whether it starts lit, its own lattice value, its colour and its next link, so they are mapped by position rather than by name. `hidden` and `reverse` are the two settings, `reverse` the invisible-from-afar flag, each read as true or false, anything else said in the report and taken as false, and `time` the clock. `public/js/orbit.js` reads a level by laying every word back into the game's file, the records in the order the blocks come and the lattice naming each, and reading that with `readKwl`, so one reader decides what a level means and the repairs above apply to the viewer's files as to any other; a block outside the lattice, a second block on a cell or a kind the game has not is left out first, with a line in the report. Of the viewer's 203 level files, 169 read back to the canonical bytes of a shipped level and the rest to no level of the disc's, and `tests/fixtures/orbit-levels.json` holds five of the 169 with the slot each is, lasers, a platform, devices and the flag among them, so the axes and the laser words are held to the disc. The share link carries the level as text, a header of `time|hidden|reverse` and a line a block, every number in base 36 with `~` for 65535 and `_` for an empty slot, gzipped and written in base64url without padding under `level=`, with the viewer's theme under `theme=`; `readOrbitLink` takes a whole URL, a query or the bare value, refuses a value that is only digits, which names one of the viewer's own levels, reads the level in the world `theme` names where that is one of the disc's and the world on screen otherwise, saying so where it is not, and `readLevelText` titles it Shared level. The link is pasted into the box the sidebar's `paste a link…` opens, which reads it in the world on screen, shows the reader's refusal under the field and keeps the field for another paste, and the result is a new draft marked saved, as a file's is. The fixture holds the link the viewer's own encoder makes of each of its five levels.

## The palette

`public/js/palette.js` builds its rows from the data rather than from a list of its own: the kinds of block are the kinds below the settings record apart from the spans, named by the annotations' kind names, and the things are the set the disc places (`PLAYED` in kwl.js) less type 4, which is untested in play, with the five fruit folded into one row writing type 46; a type the legend tells apart by a field (`objectId` splits it) has a row per variant from `VARIANTS`, keyed as the legend keys it, so the eyedropper finds a row by the same id; the groups are rules, not lists: the pickups by `PICKUPS`, what paints a face or starts the ball, then the hazards by the annotations' flag, and the rest as devices. The spans have rows of their own in the Blocks group, one for the moving platform and one laser row per colour, keyed `k8/<colour>` since the legend keys every laser as the one kind `k8`, and named `Laser (<colour>)` with the colour's word taken from the annotations' switch variants, so that the names stay the annotations' alone. `idOf` names a fruit of any of the five types by that row, so the eyedropper and the form's list find a fruit wherever it came from; a thing the palette has no row for, type 4 among them, stays in the form's list as a disabled entry named as the panel names an unnamed type, by its number, and can be taken off but not chosen anew.

## The form

`public/js/editform.js` is the panel's form while editing, drawn through the one seam the panel has, `onShow(fn)` in `public/js/detail.js`, which calls what is registered after every rebuild of the panel with the box and the cell it shows; the panel itself has no editor branch, and the form draws only while editing is on and the cell is a block of the draft, or a cell of a span's run, which gets the span's block. Every control changes one key of the project through the copy-on-write functions and one step of the trail, labelled as the editor's announcements read: the kind select writes `kind` through `setBlock`, keeping `faces` for a kind of 0 to 4 and dropping them for a crumbling or vanishing block, which the label says; the phase select writes `phase`; a platform's length and speed fields write `length` and `speed`; a laser's swatches write `colour`; the face's list writes `faces[j]` as `{ type, variant, facing }` with the palette's entry for the type and variant, a facing kept from what stood there or 1, and nothing in the list removes the key; the facing buttons write `facing`, labelled by the way the thing then points, read through the same heading rule the panel uses; the colour, worth and phase swatches write `variant`; and the circuits' buttons write `circuits` through `setCircuit`. A teleporter's "leads to" and a run's axis and far end are shown and not edited, since the links are rebuilt at every write and a run is re-laid with the tool. The refusals are the editor's, by the same conditions: a device on a block that is not plain, anything on a span's, crumbling or vanishing block's faces, a face that looks into another block, and any change the checks newly flag as an error, found by validating the changed copy, after which the control goes back to what it showed. The two buttons place through the editor's own `placeHere` and `buildAgainst`, so the keyboard path and the pointer's are one rule. The counts line reads `counts` against the caps and the disc's maxima, and the findings are `validate`'s, each linking to its cell through the panel. The control being worked is found again by its `data-field` after the panel is rebuilt by the store's update, so the focus stays where the author is.

## The checks

**The digest fixture.** `tests/fixtures/kwl-digests.json` holds, for each of the 230 shipped levels keyed by `pack#index`, the SHA-256 of its canonical file rebuilt from `public/map_data.json`, the SHA-256 of that file's zlib stream at level 6, the level the disc was packed at, and the stream's length. `python3 tools/kula_kwl.py --digests` writes it, sorted and one key a line so a rebuild diffs line by line, and the Python tests and the viewer's own writer are both held to it, so the two writers cannot drift apart without the fixture saying so. The deflate digests were written with zlib 1.2.12; zlib's output at a level has been stable across its releases, and a Python whose zlib differs would fail the deflate lines alone.

**The deflate vectors.** `tests/fixtures/deflate-vectors.json` holds four inputs, two thousand zero bytes, the word KULA five hundred times over, four kilobytes of noise and a sparse lattice of the level file's size, with the stream zlib writes for each at level 6 and at level 9, the two levels the page compresses at, and the version of zlib that wrote them, and the unit tests hold the page's vendored deflate to every stream. `python3 tools/kula_kwl.py --deflate-vectors` rewrites the streams from the inputs the fixture holds with the Python's own zlib; a vector is added by appending its name and its input, in base64, and rewriting.

**The hostile documents.** `tests/fixtures/hostile-projects.json` holds project documents written to break a reader, a face named every way a key can be spelled, a cell of two coordinates, a far end on its own cell or at 32767, a time of null, a kind of true, a type of 10^308, a blocks list that is text, with what the reader gives for each, the project and the report, and the digest of the level the writer writes for that project or the sentence it refuses it with; a document of another format carries its refusal alone. `python3 tools/kula_kwl.py --hostile` rewrites the outcomes from the documents with the Python reader and writer, a case is added by appending its name and document and rewriting, and the page's reader and writer are held to every case, so the two sides cannot answer a document differently without the fixture saying so.

**The viewer's writer.** The page writes and reads the same bytes in `public/js/kwl.js`, whose `writeKwl`, `readKwl` and `levelOf` port `canonical`, `read_kwl` and the parser, and models a level in `public/js/project.js`, which holds the project file's reader and writer, the copy-on-write edits and `validate`, `counts` and `plays_as` as above. The unit tests hold the port to the Python side through the digest fixture, both digests over all 230 templates, and through the fixed point: a template written to the game's bytes and read back is the same project, and the level the viewer draws of a project carries the shipped level's markers, by cell and by every field the renderer reads.

**The disc check.** `python3 tools/kula_kwl.py --check`, with `$KULA_DISC` set, parses every level of the disc, rebuilds it from its fields through `project_of_level` and `canonical`, and holds the rebuild to the disc two ways. In play: the rebuild passes `Level.verify`; the same cells hold the same kinds; the records both have, matched by cell, have the same kind, the same objects by face with the same type, the same facing where the type turns, the same variant where it has one and the same state, and the same spans, colours, lit flags, lengths and speeds; every switch's list reaches the same slots and every teleporter leads to the same place, by cell and face; the time and the two settings are the same. Word for word: every word of every matched record and of the trailer outside an explicit mask of what the game never reads, a link compared as the cell and face it names and a record's own lattice value as itself, so that a record folded or left out does not read as a hundred shifted words. The mask is the header word; words 96 to 118 of every record; words 13 and 15 of every slot; the kind word of slots 2 to 5; the trailer's words 1 to 5 and its slots 1 to 5; every word of a settings record but its two flags; a bare slot's words other than its type and its state; an object's `f9`, `f10` and `f14`, its `f6` and `f7` on anything but a teleporter or a switch, and its `f5` on BONUS 30, whose pickups the disc left unnumbered, and on LEVEL 134, LECEL 94, FINAL 11 and FINAL 13, where a number repeats on an object the game never walks; a platform's second slot but its end, length, speed and lattice value, and its first slot from `f10` on; a crumbling block's first slot from `f5` on and its other slots; a vanishing block's type word, its first slot from `f3` on and its other slots; and a laser's slots 2 to 5. A level whose rebuild has fewer records than the disc, 144 that carry a settings record with neither flag set and 2 that carry a record with nothing on it, is compared on the records both have and the rest is counted.

All 230 levels play as the disc's. Outside the mask the rebuild differs from the disc in these words and no others, each a class the test `tools/tests/test_kula_kwl.py` pins by its count, so a writer change that moves one is a finding and not a filler:

| words | count | what it is |
| --- | --- | --- |
| the clock's `f2` | 27 | 4 left by the editor on 27 of 51 clocks; the loader skips the turn for type 8 and never reads it |
| a platform's slots 2 to 5, the type and one `f4` | 17 | an editor's leftovers in slots the game never reads, on five of the 37 |
| a laser's `f10` and `f14` | 6 | a deleted object's constants on three lasers, in words nothing reads |
| the extras 119 to 124 of one ice block and one crumbling block | 12 | a platform's position left on LEVEL 54 and FINAL 11, read for kind 5 alone |
| the kind word of one object slot | 1 | 0 on LEVEL 71, the scratch word the game writes before it reads |
| one teleporter's `f6` | 1 | LEVEL 125's two yellow teleporters, the one chain of the disc left unlinked, which nothing walks since the colour has no switch |
